Contents & overview

What this project does

A teaching simulator for the short-term CPU scheduler.

01

The project is a complete browser-based CPU scheduling simulator. The user builds a process list, selects one of six algorithms, sets a time quantum for Round Robin, and runs the simulation. A Flask backend validates the request, executes the chosen algorithm in pure Python, calculates the performance metrics, and returns JSON. The browser then draws a custom Gantt chart, a per-process metrics table, summary cards and—on request—a six-algorithm comparison with Chart.js bar charts.

What the user can do

  • Add, edit and delete processes with PID, arrival, burst and priority.
  • Load a five-process sample or clear the list.
  • Run any single algorithm and inspect the schedule.
  • Compare all six algorithms on identical inputs.
  • Read CT, TAT, WT, RT, averages and CPU utilization.
  • Hover or focus Gantt blocks for start and end times.

What the system guarantees

  • Consistent tie-breaking: primary key, arrival, then PID.
  • Simultaneous arrivals become available together.
  • Idle CPU time is shown as an Idle block.
  • Round Robin follows the arrival-at-expiry queue rule.
  • Every algorithm uses the same metric formulas.
  • Invalid input is rejected with a clear inline message.

Scheduling logic

How the CPU assigns tasks

This is a simulation of a short-term scheduler, not the real OS scheduler.

03

Each process record in the browser is a simplified PCB: PID, arrival time, burst time, priority and the derived scheduling fields. The scheduler keeps a ready set of processes that have arrived and still need CPU time. At each decision point it selects one process, runs it for an interval, records a Gantt block, and updates the remaining work.

Decision loop

1
Build available set

arrival ≤ now and remaining burst > 0.

2
Choose by policy

Apply the algorithm's primary key, then arrival, then PID.

3
Run an interval

To completion, to the next arrival, or for one quantum.

4
Record and update

Append a block, reduce remaining time, record completion.

5
Repeat or idle

If nobody is ready, add an Idle block and jump to the next arrival.

When does the scheduler choose?

Algorithm styleDecision points
Non-preemptive
FCFS, SJF, Priority		When the CPU becomes idle: at the start, or after a process completes.
Preemptive
SRTF, Preemptive Priority		When a new process arrives, plus when the CPU becomes idle.
Round RobinWhen a quantum expires, when the CPU becomes idle, and when a new arrival enters the ready queue.

Lower priority number = higher priority. A new process preempts only when its priority number is strictly smaller than the running process's priority. Equal priority keeps the earlier arrival on the CPU. Round Robin arriving exactly at quantum expiry enters the ready queue before the preempted process is re-added.

Simultaneous arrivals

All processes with the same arrival time are available together and ordered by the same tie-breaking keys.

Idle CPU

If the available set is empty, an Idle block is added and time jumps to the next arrival.

Gantt merging

Adjacent blocks of the same process are merged, especially after Round Robin slices or no-preemption arrivals.

01

First Come, First Served (FCFS)

Non-preemptive

Processes are ordered by arrival time. The earliest arrival runs until it finishes. If two processes arrive together, the smaller Process ID runs first. This is the simplest policy and the baseline for comparison.

Selection

Minimum (arrival, PID); no later arrival can interrupt.

Tie-break

Earlier arrival, then smaller PID (natural order: P2 before P10).

sort processes by (arrival, PID)
time = 0
for each process:
    if time < arrival: add Idle block; time = arrival
    run process from time to time + burst
    record start and completion
+ Trivial to implement; no starvation; low overhead.
− Convoy effect: short jobs wait behind one long job.
02

Shortest Job First (SJF)

Non-preemptive

Among the processes that have already arrived, the smallest burst time runs next and completes. SJF usually lowers average waiting and turnaround time because short jobs do not wait behind long ones.

Selection

Minimum (burst, arrival, PID) among available processes.

Tie-break

Equal burst → earlier arrival → smaller PID.

pending = all processes; time = 0
while pending:
    available = {p | p.arrival <= time}
    if available is empty: idle to next arrival
    chosen = min(available, key = (burst, arrival, PID))
    run chosen to completion; record it
+ Good average TAT/WT for known batch workloads.
− Long jobs can starve; real burst times are estimates.
Algorithm reference · part 2

SRTF and Round Robin

Shortest-remaining-time preemption versus fixed time slicing.

04
03

Shortest Remaining Time First (SRTF)

Preemptive

SRTF is preemptive SJF. At every arrival it compares the remaining burst times of all available processes. A new process with a strictly shorter remaining time preempts the running process immediately.

Selection

Minimum (remaining, arrival, PID); re-evaluated at every arrival.

Tie-break

Equal remaining → earlier arrival → smaller PID. Equal remaining does not preempt.

remaining = burst for every process; time = 0
while unfinished:
    available = {p | arrived and remaining[p] > 0}
    if empty: idle to next arrival
    chosen = min(available, key = (remaining, arrival, PID))
    run until completion or next arrival, whichever is first
    update remaining; record block and completion
+ Short jobs get CPU quickly; can lower average TAT/WT.
− Long jobs may starve; more preemptions than SJF.
04

Round Robin (RR)

Preemptive

Each ready process runs for at most one time quantum. If it does not finish, it goes to the back of the FIFO ready queue. New arrivals enter the queue in arrival/PID order; a process arriving exactly when a quantum expires enters before the preempted process is re-added.

Selection

Leftmost process in the ready queue; run min(quantum, remaining).

Tie-break

Queue order on entry: earlier arrival, then smaller PID.

ready = empty FIFO queue; time = 0
enqueue arrivals up to time
while unfinished:
    if ready empty: idle to next arrival; enqueue arrivals
    p = ready.popleft()
    run p for min(quantum, remaining[p])
    enqueue new arrivals at the new time
    if p unfinished: ready.append(p)   # preempted process goes last
    else: record completion
+ Fair; good response time; no starvation for finite bursts.
− More switches; a very large quantum behaves like FCFS.

The two priority policies

Same importance rule; one waits, one can preempt.

05

Priority Scheduling

Non-preemptive

Among arrived processes, the smallest priority number runs to completion. This is useful when important work must go first, but a continuously arriving stream of high-priority work can starve low-priority processes. Aging is not implemented.

Selection

Minimum (priority, arrival, PID) among available processes.

Tie-break

Equal priority → earlier arrival → smaller PID.

pending = all processes; time = 0
while pending:
    available = {p | p.arrival <= time}
    if empty: idle to next arrival
    chosen = min(available, key = (priority, arrival, PID))
    run chosen to completion; record it
+ Models importance; simple non-preemptive variant.
− Low-priority starvation; priority must be assigned sensibly.
06

Preemptive Priority

Preemptive

The running process is interrupted when a newly arrived process has a strictly smaller priority number. Equal priority keeps the earlier-arrived process running. SRTF and Preemptive Priority share the same _preemptive() engine; only the selection key differs.

Selection

Minimum (priority, arrival, PID); re-evaluated at every arrival.

Tie-break

Equal priority → earlier arrival → smaller PID. Equal priority does not preempt.

remaining = burst for every process; time = 0
while unfinished:
    available = {p | arrived and remaining[p] > 0}
    if empty: idle to next arrival
    chosen = min(available, key = (priority, arrival, PID))
    run until completion or next arrival, whichever is first
    update remaining; record block and completion
+ Critical work gets immediate CPU; improves response time.
− Starvation; more preemptions than non-preemptive Priority.
Shared implementation: SJF and non-preemptive Priority share _non_preemptive(); SRTF and Preemptive Priority share _preemptive(). Round Robin is independent because it uses a fixed quantum and a FIFO queue.

Rejected inputs

  • Empty process list, or more than 100 processes.
  • Empty, invalid, reserved or duplicate Process ID.
  • Negative arrival or priority.
  • Burst time of 0 or less.
  • Decimal or non-numeric time values.
  • Missing quantum, or quantum ≤ 0 for Round Robin.
  • Unknown algorithm key or malformed JSON.

Errors appear inline, not in browser alerts.

All times are whole-number units. This keeps the Gantt chart and formulas exact. Decimal values such as 2.5 are rejected rather than rounded silently. The maximum list size is 100 processes.
Outputs & formulas

What the simulator returns

A timeline, one row per process, and a small metrics object.

06

Gantt timeline

A chronological list of {pid, start, end} blocks. Idle marks no ready process; adjacent same-process blocks are merged.

Per-process rows

PID, arrival, burst, priority, first start, completion, TAT, WT and RT. Returned in the user's input order.

Summary metrics

Average TAT/WT/RT, CPU utilization, process count, busy time, idle time and total elapsed time.

Definitions and formulas

Completion timeCTiTime at which process i finishes its burst.
Turnaround timeTATi = CTi − ATiTotal time from arrival to completion.
Waiting timeWTi = TATi − BTiTime spent waiting, excluding its own execution.
Response timeRTi = first_starti − ATiDelay before the first CPU allocation.
Average metricavg = (1/n) Σ valueiApplied to TAT, WT and RT.
CPU utilization(busy ÷ elapsed) × 100Busy blocks only; elapsed is 0 to the last completion.

Reading the output

  • CT is the end of the process's last block.
  • TAT includes waiting and execution.
  • WT is zero if the process starts immediately.
  • RT stops at the first start; it can differ from WT after preemption.
  • Busy is the sum of non-idle block durations.
  • Total elapsed includes initial idle time from t = 0.
  • Best means minimum average TAT/WT/RT and maximum CPU utilization; ties are preserved.
Non-preemptive shortcut: if a process runs once to completion, its first start equals completion minus burst, so RT = WT. In SRTF, Preemptive Priority and Round Robin, the two can differ because a process may be interrupted and resume later.

Viva summary

This project is a Flask-served, browser-based simulator that runs FCFS, SJF, SRTF, Round Robin, non-preemptive Priority and Preemptive Priority scheduling in pure Python. It returns a merged Gantt timeline and CT/TAT/WT/RT metrics as JSON, and visualises the results with a custom Gantt chart and Chart.js comparison charts. It is a teaching simulation, not a real OS scheduler.
